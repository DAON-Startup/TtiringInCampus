# WORKFLOW.md — 마스터 AI 에이전트 자동화 워크플로우

## 개요

이 문서는 마스터 에이전트가 서브 에이전트들을 조율하여 프로젝트를 기획→제작→운영까지 자동화하는 전체 워크플로우를 정의한다. 이 워크플로우는 향후 다른 프로젝트에도 재사용할 수 있도록 설계되었다.

## 실행 환경

### 개발 단계 (Phase 1~3): Claude Code Agent Teams
- 마스터 에이전트 = Claude Code의 메인 세션
- 서브 에이전트 = `.opencode/agents/` 또는 Agent Teams의 서브 에이전트
- 통신 = P2P 메일박스 또는 파일 기반 메시지 전달
- 모델 = Opus 4.6 (마스터, 설계, 개발) / Sonnet 4.6 (리서치, 기획, 디자인)

### 운영 단계 (Phase 4): n8n
- 운영 에이전트의 반복 작업 = n8n 워크플로우
- 비정형 판단 = Claude API 호출 (n8n HTTP Request 노드)
- 트리거 = Cron, Webhook, Notion 상태 변경

### 하이브리드 구간
- Phase 3 후반~Phase 4 초반은 Claude Code와 n8n이 병행
- n8n 워크플로우 자체도 개발 에이전트가 코드로 작성

### Phase 1: 기획 자동화

**소요 예상**: 3~5일

```
[시작] 마스터 에이전트 활성화
  │
  ├─[1.1] 마스터 → 리서치 에이전트 호출
  │   ├── 작업 1: 경쟁사 분석 (5개+ 서비스)
  │   ├── 작업 2: 레퍼런스 수집 (5개 카테고리)
  │   ├── 작업 3: 기술 조사 (크롤링 가능성)
  │   ├── 작업 4: 비용 시뮬레이션 (4개 시나리오)
  │   └── 출력 → Notion 01_기획/리서치_*/
  │
  ├─[1.2] 마스터: 리서치 결과 품질 확인
  │   ├── 경쟁사 5개 이상 분석 완료? → ✓/✗
  │   ├── 레퍼런스 카테고리당 3개 이상? → ✓/✗
  │   ├── 크롤링 대상 URL 구조 파악 완료? → ✓/✗
  │   └── 미달 시: 리서치 에이전트에 보완 요청
  │
  ├─[CP-1] 사람 승인: 리서치 결과 검토
  │   ├── 승인 → 1.3으로
  │   ├── 수정 → 리서치 에이전트 재작업 → 1.2로
  │   └── 반려 → 리서치 방향 재설정 후 1.1로
  │
  ├─[1.3] 마스터 → 기획 에이전트 호출
  │   ├── 입력: 승인된 리서치 결과 + PROJECT_CONTEXT
  │   ├── 작업 1: 서비스 요구사항 문서 작성
  │   ├── 작업 2: MVP 범위 정의서 작성
  │   ├── 작업 3: 사용자 플로우 정의
  │   └── 출력 → Notion 01_기획/요구사항_문서/
  │
  ├─[1.4] 마스터: 기획 결과 품질 확인
  │   ├── 모든 MVP 기능에 요구사항 ID? → ✓/✗
  │   ├── 사용자 스토리 + 인수 조건 포함? → ✓/✗
  │   ├── 비기능 요구사항 7개 이상? → ✓/✗
  │   └── 미달 시: 기획 에이전트에 보완 요청
  │
  └─[CP-2] 사람 승인: 요구사항/MVP 범위 확정
      ├── 승인 → Phase 2로
      ├── 수정 → 기획 에이전트 재작업 → 1.4로
      └── 반려 → 1.3으로 (요구사항 전면 재작성)
```

## 재사용 가이드

이 마스터 에이전트 시스템을 다른 프로젝트에 재사용하는 방법:

### 1. 프로젝트별 커스터마이징 대상
| 파일 | 변경 항목 |
|------|-----------|
| `PROJECT_CONTEXT.md` | 전면 교체 (프로젝트 도메인, 기능, 스택) |
| `CRAWLING_RESILIENCE_SKILL.md` | 크롤링 프로젝트인 경우만 수정, 아니면 삭제 |
| 각 에이전트의 "산출물 목록" | 프로젝트 요구에 맞게 조정 |

### 2. 프로젝트별 불변 항목 (재사용)
| 파일 | 이유 |
|------|------|
| `MASTER_AGENT.md` 파이프라인 구조 | Phase 1~4 구조는 대부분의 프로젝트에 적용 가능 |
| `HUMAN_CHECKPOINT_SKILL.md` | 사람 승인 프로토콜은 보편적 |
| `NOTION_WRITE_SKILL.md` | Notion 저장 규칙은 보편적 |
| `WORKFLOW.md` 아키텍처 | 에이전트 조율 패턴은 보편적 |

### 3. 새 프로젝트 시작 절차
```
1. PROJECT_CONTEXT.md를 새 프로젝트에 맞게 작성
2. 필요 없는 에이전트 제거 (예: 크롤러 없으면 CRAWLING_RESILIENCE_SKILL 삭제)
3. 필요한 에이전트 추가 (예: 마케팅 에이전트)
4. MASTER_AGENT.md의 Phase별 STEP 조정
5. WORKFLOW.md의 상세 플로우 업데이트
6. 마스터 에이전트 실행 → Phase 1 시작
```
