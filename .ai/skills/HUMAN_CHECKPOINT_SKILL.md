# HUMAN_CHECKPOINT_SKILL.md — 사람 승인 요청 프로토콜

## 목적
AI 에이전트의 작업 결과물이 다음 단계로 넘어가기 전에 사람의 검토와 승인을 받는 표준 절차를 정의한다.

## 원칙
1. **AI는 제안하고, 사람이 결정한다** — 모든 단계 전환은 사람 승인 필수
2. **맥락을 함께 전달한다** — 승인 요청 시 판단에 필요한 정보를 구조화하여 제공
3. **승인/반려/수정 3가지 경로를 항상 제공한다**

## 체크포인트 목록

| ID | 시점 | 승인 대상 | 판단 기준 |
|----|------|-----------|-----------|
| CP-1 | 리서치 완료 후 | 리서치 결과 (경쟁사 분석, 레퍼런스, 기술 조사, 비용) | 충분한 정보가 수집되었는가, 누락된 조사 항목이 없는가 |
| CP-2 | 기획 완료 후, Phase 2 진입 전 | 요구사항 문서, MVP 범위 정의서, 사용자 플로우 | 기능 목록과 우선순위가 현실적인가, MVP 범위가 적절한가 |
| CP-3 | Phase 2 → 3 전환 | ERD, API 명세, 아키텍처, 디자인 | 설계 문서 간 정합성이 맞는가, 기술 선택이 적절한가 |
| CP-4 | Phase 3 → 4 전환 | 완성 코드 + 테스트 결과 | 핵심 기능이 동작하는가, 배포 준비 완료인가 |
| CP-5 | Phase 4 안정화 후 | 운영 메트릭 리포트 | 자기개선 루프 진입 조건 충족했는가 |

## 승인 요청 메시지 형식

에이전트가 사람에게 승인을 요청할 때는 아래 형식을 따른다:

```markdown
## 🔔 체크포인트 [CP-ID] 승인 요청

### 현재 단계
[현재 Phase와 완료된 작업 요약]

### 산출물 목록
1. [산출물 1] — [Notion 링크 또는 파일 경로]
2. [산출물 2] — [Notion 링크 또는 파일 경로]

### 핵심 판단 포인트
- [사람이 주의 깊게 봐야 할 사항 1]
- [사람이 주의 깊게 봐야 할 사항 2]

### AI 자체 평가
- 완성도: [상/중/하]
- 우려 사항: [있으면 명시, 없으면 "없음"]
- 추가 작업 필요 여부: [있으면 명시]

### 요청 사항
- [ ] 승인 → 다음 단계 [Phase X] 진행
- [ ] 수정 요청 → 구체적 피드백 작성
- [ ] 반려 → 현재 단계 재작업
```

## 승인 대기 중 행동 규칙

1. 승인 대기 중에는 해당 Phase의 작업을 더 진행하지 않는다
2. 단, 현재 Phase 내에서 독립적인 보완 작업(문서 정리, 자체 검증 등)은 가능하다
3. 승인 대기 상태를 Notion의 프로젝트 상태 필드에 반영한다
4. 48시간 이상 응답이 없으면 리마인더를 1회 발송한다

## 수정 피드백 처리 절차

1. 사람의 수정 피드백을 수신한다
2. 피드백 내용을 구조화하여 해당 에이전트에게 전달한다
3. 에이전트가 수정 작업을 완료한다
4. 수정 전/후 diff를 포함하여 재승인을 요청한다
5. 최대 3회 수정 루프까지 허용하며, 3회 초과 시 마스터 에이전트가 사람과 직접 논의를 요청한다

## n8n 연동 (Phase 4 운영 단계)

운영 단계에서는 n8n 워크플로우를 통해 자동 체크포인트를 구현할 수 있다:
- Notion 페이지의 `상태` 프로퍼티가 "검토 요청"으로 변경되면 n8n이 감지
- 사람에게 알림 발송 (Slack/카카오톡/이메일)
- 사람이 "승인됨"으로 상태 변경하면 n8n이 다음 워크플로우 트리거
