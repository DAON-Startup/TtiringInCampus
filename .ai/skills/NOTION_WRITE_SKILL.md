# NOTION_WRITE_SKILL.md — Notion 문서 작성 표준

## 목적
모든 에이전트가 Notion에 결과물을 저장할 때 일관된 형식과 방법을 따르도록 한다.

## 핵심 규칙

### 1. 페이지 생성 규칙
- 모든 산출물은 `PROJECT_CONTEXT.md`의 "Notion 문서 구조"에 정의된 위치에 저장한다
- 페이지 제목은 `[에이전트명] 산출물명 (YYYY-MM-DD)` 형식을 따른다
    - 예: `[설계] ERD v1.0 (2026-04-01)`
- 페이지 아이콘은 단계별로 통일한다:
    - 기획: 📋, 설계: 🏗️, 디자인: 🎨, 개발: 💻, 인프라: ☁️, 운영: 📊

### 2. 콘텐츠 구조 규칙
- 모든 문서는 아래 메타 정보 블록으로 시작한다:

```markdown
> **작성 에이전트**: [에이전트명]
> **작성 일시**: [YYYY-MM-DD HH:MM]
> **버전**: [v1.0]
> **상태**: [초안 / 검토중 / 승인됨 / 수정중]
> **이전 버전**: [있으면 Notion 링크, 없으면 "최초 작성"]
```

- 본문은 개요 → 내용 → 요약 구조를 따른다
- 비교 항목은 표(table) 형식을 사용한다
- 개인 정보는 포함하지 않는다 (Notion 문서는 공식 문서로 사용됨)

### 3. Notion API 사용 시 주의사항
- `notion_append_block_children`은 1회 호출당 100블록 제한
- 100블록 초과 시 여러 번에 나눠 호출한다
- 토글 헤딩: `heading_2`에 `is_toggleable: true` 설정
- 중첩 불릿: `children` 배열로 구현
- `notion_delete_block`은 블록 단위로만 가능 (벌크 삭제 불가)
- 페이지 ID는 하이픈 포함 UUID 형식 사용
- 전체 페이지 덮어쓰기 시 `replace_content` 명령 사용

### 4. 버전 관리
- 문서 수정 시 버전 번호를 올린다 (v1.0 → v1.1 → v2.0)
- v1.x: 마이너 수정 (오타, 보완)
- vX.0: 메이저 변경 (구조 변경, 대폭 수정)
- 이전 버전은 삭제하지 않고 제목에 `[Archive]`를 붙여 보관한다

### 5. 상태 필드 관리
- 에이전트가 문서를 생성하면 상태를 "초안"으로 설정
- 자체 검증 완료 후 "검토중"으로 변경
- 사람이 승인하면 "승인됨"으로 변경
- 수정 요청 시 "수정중"으로 변경 후 작업, 완료 시 "검토중"으로 복귀

### 6. 태그 규칙
- 단계 태그: `기획`, `설계`, `디자인`, `개발`, `인프라`, `운영`
- 문서 유형 태그: `요구사항`, `ERD`, `API명세`, `아키텍처`, `리서치`, `회의록`
- 에이전트 태그: `AI생성`, `사람수정`, `AI+사람`
