# PROJECT_CONTEXT.md — 프로젝트 공유 컨텍스트

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | 대학교 통합 공지사항 앱 서비스 |
| 목표 | 대학교의 모든 공지사항을 하나의 앱에서 통합 제공하여 정보 접근성을 극대화 |
| 대상 사용자 | 인천대학교 재학생 (확장 시 타 대학교) |
| 핵심 가치 | "사용자가 정보를 찾는 것이 아니라, 정보가 사용자에게 찾아오게 한다" |

## 2. 핵심 문제 정의

### 문제 1: 사용자 니즈 미반영
- 기존 스마트캠퍼스 앱은 학사/일반·행사/장학 3개 카테고리만 제공
- 실제로는 학과, 생활원, StarINU, 취업경력개발원 등의 공지 열람 빈도가 훨씬 높음

### 문제 2: 정보 조회에 오래 걸리는 시간
- 웹 검색 → 학생 로그인 → 단과대학 → 학과 → 공지사항: 총 4~5단계

### 문제 3: 정보의 파편화
- 공지사항들이 각기 다른 사이트에 흩어져 있어 교차 열람이 불편

## 3. MVP 핵심 기능 (우선순위순)

| 우선순위 | 기능 | 설명 |
|----------|------|------|
| 최상 | AI 정기 리포트 | 크롤링된 공지를 LLM으로 요약하여 매일 아침/저녁 푸시 |
| 상 | 통합 공지사항 | 학교 모든 공지를 하나의 앱에서 카테고리별 통합 열람 |
| 상 | 자동 로그인 | 최초 1회 로그인 후 자동 인증 유지 |
| 상 | 키워드 푸시 알림 | 사용자가 설정한 키워드 포함 공지 발생 시 푸시 |
| 상 | 공지 보관함 & 공유 | 공지사항 저장 및 URL 공유 |
| 중하 | MCP 연동 | 추후 확장 (미정) |

## 4. 기술 스택

| AI/LLM | Claude API / 로컬 오픈소스 LLM (비용 최적화) |

## 5. 크롤링 대상 (인천대학교 기준)

| 카테고리 | 소스 URL 패턴 | 비고 |
|----------|---------------|------|
| 학사 공지 | inu.ac.kr 포탈 | 스마트캠퍼스 기존 제공 |
| 일반/행사 | inu.ac.kr 포탈 | 스마트캠퍼스 기존 제공 |
| 장학 | inu.ac.kr 포탈 | 스마트캠퍼스 기존 제공 |
| 학과 공지 | 각 학과 홈페이지 | 단과대별 URL 구조 상이 |
| 생활원 | 생활원 홈페이지 | 별도 도메인 가능 |
| StarINU | StarINU 포탈 | 비교과 활동 정보 |
| 취업경력개발원 | 취업경력개발원 사이트 | 채용/인턴십 정보 |
| 학식 메뉴 | 생협/학식 페이지 | 일별 메뉴 크롤링 |

> **주의**: 실제 URL은 PoC 단계에서 리서치 에이전트가 수집하여 이 문서에 업데이트해야 함

## 6. 프로젝트 단계 (Pipeline)

```
Phase 1: 기획     → 리서치 에이전트 + 기획 에이전트
Phase 2: 설계     → 설계 에이전트 + 디자인 에이전트 (병렬)
Phase 3: 개발     → 개발 에이전트 + 인프라 에이전트 (병렬)
Phase 4: 운영     → 운영 에이전트 (상시)
Phase 5: 자기개선 → 메타 에이전트 (Phase 1~4 완주 후)
```

## 7. 사람 승인 체크포인트

모든 Phase 전환 시 반드시 사람이 검토·승인해야 함:

1. **CP-1**: 리서치 결과 검토 → 기획 진입 승인
2. **CP-2**: 요구사항/MVP 범위 확정 → 설계 진입 승인
3. **CP-3**: ERD/API 명세/아키텍처/디자인 확정 → 개발 진입 승인
4. **CP-4**: 코드 리뷰 완료 + 테스트 통과 → 배포 승인
5. **CP-5**: 운영 안정성 확인 → Phase 5(자기개선) 진입 승인

## 9. 비용 시뮬레이션 기준

| 항목 | 예상 규모 | 비고 |
